# Project Atlas — Product Requirements Document

Version: 0.1  
Status: Discovery and initial build  
Primary user: Arhan Sibal

## 1. Vision

Build an AI-native personal operating partner that helps Arhan consistently identify, begin and complete the highest-value work across career, learning, health and relationships.

Project Atlas should reduce decision fatigue, compensate for inconsistent task initiation and tracking, detect when execution is drifting, and provide concrete interventions that help Arhan regain momentum.

The system should simultaneously serve as a practical AI and agent-engineering laboratory.

## 2. Core problem

Arhan has many valuable and competing priorities but struggles with:

- Deciding what to work on
- Beginning tasks despite understanding their importance
- Sustaining focused work
- Recording what has been completed
- Seeing when several low-output days are accumulating
- Maintaining progress across both urgent and long-term priorities
- Translating broad ambitions into executable daily actions

A conventional task manager may store work without improving execution. Atlas must therefore support behavior, not merely organization.

## 3. Primary outcomes

### Outcome 1: Secure a strong long-term role

Support job discovery, applications, networking, interview preparation, follow-ups, opportunity prioritization and recruiting-process management.

### Outcome 2: Become deeply current in AI, technology and business

Build a sustainable information and learning system covering structured courses, important developments, durable concepts and applied projects.

### Outcome 3: Become organized and disciplined

Create a repeatable operating rhythm in which planning, starting, tracking, reviewing and recovering from low-output periods become easier.

### Outcome 4: Build applied AI capability

Use Atlas itself to learn AI product design, automation, context engineering, tool use, agents, APIs, evaluation and human-in-the-loop systems.

## 5. Five operating brains

### Executive Assistant

Manages commitments, communications, schedule awareness, deadlines and follow-ups.

### Career Coach

Tracks opportunities, applications, people, interviews, positioning and recommended career actions.

### Learning Coach

Plans and tracks AI learning, executive-presence development, interview practice, courses and knowledge retention.

### Accountability Partner

Tracks planned versus completed work, identifies execution drift, asks useful reflection questions and supports recovery.

### Strategic Advisor

Evaluates whether time and effort remain aligned with the user's highest-value outcomes.

## 6. Initial user experience

Atlas should eventually provide:

### Morning activation

- A very small set of priorities
- A recommended first task
- A deliberately easy starting action
- Suggested focus blocks
- Relevant appointments and deadlines
- Any urgent follow-ups

### During-work support

- Clear next actions
- Low-friction task-starting instructions
- Focus-session tracking
- Rapid capture of interruptions and new tasks
- Restart support after distraction

### Evening closure

- Work completed
- Time spent
- Unfinished items
- Obstacles encountered
- Tomorrow's likely first action

### Weekly review

- Progress toward major outcomes
- Planned versus completed effort
- Stalled projects
- Neglected domains
- Important wins
- Recommended changes for the next week

## 7. Success metrics

Initial metrics will be baselined before targets are finalized.

Candidate measures include:

- Focused or purposeful hours per week
- Number of days with at least one completed focus block
- Time between deciding to work and beginning
- Percentage of planned priority work completed
- Job-search activity and funnel progress
- Networking follow-ups completed
- Interview-practice sessions completed
- Structured AI-learning hours
- Weekly review completion
- Frequency and duration of execution slumps
- System usage burden

The system must not succeed merely by increasing data entry.

## 8. Product principles

1. Execution over documentation.
2. Fewer visible choices when action is required.
3. The system must support recovery, not punish missed plans.
4. Human approval is required for consequential external actions.
5. Automate only workflows that have first been understood.
6. Every automation must be observable and reversible.
7. The system should progressively learn from actual behavior.
8. The simplest useful version should be shipped first.
9. One source of truth should exist for each important data type.
10. Building Atlas should generate reusable AI-engineering knowledge and portfolio evidence.

## 9. Initial constraints

- Atlas will begin with Notion as the structured operating layer.
- Google Calendar will remain the authoritative source for calendar events.
- Gmail will remain the authoritative source for email.
- GitHub will store code, technical documentation and version-controlled artifacts.
- ChatGPT will initially serve as product lead, mentor and reasoning partner.
- External agents will receive only the minimum permissions required.
- Automated sending, deleting, financial transactions and other consequential actions will not be enabled during early phases.
- The initial build must become useful before becoming comprehensive.

## 10. Initial scope

The first usable release will focus on:

- Goals
- Projects
- Tasks
- Daily execution
- Basic weekly review
- A lightweight job-search structure

It will not initially include:

- Autonomous email processing
- Automatic calendar changes
- Multi-agent orchestration
- Complex knowledge ingestion
- Fully automated scheduling
- A custom application interface

## 11. Open questions

- What morning briefing format produces action rather than avoidance?
- Should planned work be measured in time, outputs or both?
- How much daily data entry remains sustainable?
- Which interventions work best when initiation is difficult?
- How should Atlas distinguish meaningful rest from avoidance?
- What job-search metrics predict progress without encouraging low-quality activity?
- Which information sources deserve inclusion in the AI/business/technology briefing?
- Which responsibilities should remain with ChatGPT, Notion agents, coded agents and workflow automation?
